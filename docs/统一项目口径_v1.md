# 统一项目口径 v1

> 用途：作为论文主稿、README、验收矩阵、MIS 页面、汇报材料的统一口径源。
> 
> 适用对象：项目负责人、论文写作者、算法开发者、前端展示维护者、汇报材料整理者。

---

## 1. 项目一句话定位

本项目是一个面向县域秋葵主产区冷链设施规划的 **研究级决策优化系统**。其核心是 `v3.0 capacity-chain MIP` 模型与 `direct Gurobi solve` 精确求解链条，并通过 `AI-guided warm start` 提升主求解器搜索效率；`Benders cut ranking / robustness` 则作为方法学子线，用于探讨 AI 在 cut 优先级管理中的可解释作用与鲁棒性边界。

---

## 2. 项目主线与支线

### 2.1 主线（必须优先说）

1. **主模型：** `v3.0 capacity-chain MIP`
2. **主求解器：** `direct Gurobi solve`
3. **最强 AI 证据：** `AI-guided warm start`
4. **主口径数据：** `OSM road-network matrix`（若引用历史近似结果，必须显式标记）

### 2.2 支线（可以说，但必须带边界）

1. `Benders cut ranking / robustness`
2. `learned cut ranking`
3. `cut prioritization`
4. `SPO / data-driven parameter learning`

### 2.3 明确不能反客为主的内容

以下内容不能被写成项目唯一主线：

- AI-Benders 显著加速整个主模型
- Benders 是当前 v3.0 的主生产求解器
- 现有 MIS 已达到企业级生产标准
- 当前县域案例已经完成企业级泛化验证

---

## 3. 算法口径统一模板

### 3.1 安全主说法

> 本项目当前的主优化链条是 `v3.0 capacity-chain MIP + direct Gurobi solve`。在该链条上，`AI-guided warm start` 提供了最强且最稳的 AI 增强证据：AI 不改变模型、目标函数或最终决策逻辑，只为精确求解器提供更高质量的起始解，从而缩短搜索时间。

### 3.2 Benders 安全说法

> Benders 相关工作在本项目中主要承担机制研究与方法学探索角色。当前可安全主张的是 `cut ranking / robustness` 与 `cut prioritization` 在 Benders 子线中的解释性与鲁棒性边界，而不是对朴素 cut-budget 策略的通用显著加速。

### 3.3 不安全说法（禁止）

- AI-Benders 显著加速了整个秋葵主模型。
- 学习式 cut 丢弃普遍优于经典 Benders。
- 当前 Benders 路线已经取代 direct Gurobi solve 成为主求解器。

---

## 4. 数据口径统一模板

### 4.1 主口径

> 当前论文级主结果与展示主结果应优先采用 `OSM road-network matrix` 口径，并明确其来源为公开路网抓取与后处理后的道路网络距离 / 时间矩阵。

### 4.2 历史近似口径

> `Haversine + detour factor` 口径属于项目早期基线与历史近似口径，可用于说明模型演进过程与近似误差上界，但若继续引用，必须明确标注为近似结果，而不能与 OSM 主口径混写。

### 4.3 对外统一话术

- **论文中：** 写清楚「主结果基于 OSM 路网矩阵；历史 Haversine 结果仅用于对照或揭示误差上界」。
- **README 中：** 写清楚「项目已从经纬度近似矩阵推进到 OSM 路网主口径」。
- **MIS 中：** 页面应使用 badge 或 note 标注 `OSM 主口径` / `Haversine 近似`。

## 5. MIS 口径统一模板

### 5.1 可以安全对外表述为

> 本项目已形成一个面向县域案例研究的可运行 MIS / 决策展示系统，包含 FastAPI 后端、Vue 多视图前端、PostgreSQL / PostGIS 数据库接入、高德地图底图和证据链只读展示能力。

### 5.2 必须附带的边界

> 当前 MIS 的核心定位是研究级决策驾驶舱与演示系统，尚未达到企业级生产部署、完整权限治理、审批流、IoT 联调和多角色日常运营系统的成熟度。

### 5.3 禁止写法

- 完整企业级生产 MIS 已完成
- 可直接在企业全业务链路投入生产
- 已完成真实物流系统全面联调

## 6. 论文、README、MIS 的统一映射

| 场景 | 应该怎么说 | 不应该怎么说 |

| 论文摘要 | AI-guided warm start 为主加速证据 | AI-Benders 全面显著加速 |

## 7. 统一可复制说法

### 7.1 对老师 / 评审 / 汇报场景

> 我们当前最稳的主线是：在 `v3.0 capacity-chain MIP` 上，采用 `direct Gurobi solve` 做精确求解，并通过 `AI-guided warm start` 在不改变模型与最优性逻辑的前提下显著缩短搜索时间。Benders 相关 AI 工作则主要定位为 cut 管理机制研究，不主张对朴素策略的通用显著加速。

### 7.2 对 README / 项目介绍场景

> 本项目是一个面向县域秋葵主产区冷链设施规划的研究级优化与决策展示系统。其核心包含 v3.0 capacity-chain MIP、OSM 路网口径、AI-guided warm start、以及面向证据链展示的 Vue + FastAPI + PostgreSQL / PostGIS MIS。

### 7.3 对 MIS 页面文案场景

> 本页展示的是县域案例下的主优化链条与证据链结果。`AI-guided warm start` 负责增强精确求解器的搜索效率；`Benders cut ranking / robustness` 负责解释 cut 管理中的优先级与机制边界。两者角色不同，不能混写为同一种「AI 全面加速」。

## 8. 更新规则

当以下任一内容发生变化时，必须同步更新本文件：

1. 论文主稿的主结论或边界变化。
2. warm start 策略从 V1 升级到 V2 / V3 后，最终采用版本改变。
3. OSM / Haversine 的主口径位置变化。
4. MIS 页面定位发生变化。
5. Benders 线新增了足以改变边界判断的强证据。

---

## 9. 结论

本项目当前最需要的不是扩写更多口号，而是固定一个**可信、可复现、可解释、可统一传播**的故事。统一口径的核心不是「保守」，而是让论文、工程与演示三条线在同一个事实上汇合，从而为后续企业级升级与路线设计打下稳定基础。
