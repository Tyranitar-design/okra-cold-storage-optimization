## 一、双层多目标混合整数规划模型 (Bi-level Multi-objective MIP)

### 1.1 模型定位

本项目构建的是一个**双层多目标混合整数规划模型**，其核心特征为：
- **双层结构**：上层决策设施选址与容量配置，下层优化需求分配
- **多目标优化**：同时最小化总成本、损耗吨数、碳排放吨数
- **混合整数**：包含二元决策变量（设施开放）和连续变量（分配比例）

### 1.2 集合与参数

**集合 (Sets)**：
- $I$ — 需求节点集合（村/乡镇/县，39个节点）
- $J$ — 候选设施节点集合（27个候选点）
- $T$ — 冷库类型集合（预冷/冷藏/气调/冷冻）
- $C$ — 容量等级索引集合（因设施类型而异）

**参数 (Parameters)**：
- $d_i$ — 需求节点 $i$ 的秋葵年产量（吨）
- $s_t$ — 通道份额：通道 $t$ 的需求占比（预冷50%/冷藏30%/气调15%/冷冻10%，场景假设）
- $\text{dist}_{ij}$ — 节点 $i$ 到候选点 $j$ 的OSM路网距离（km）
- $f_{tc}, o_{tc}$ — 类型 $t$ 容量等级 $c$ 的固定成本、运营成本（万元）
- $\text{cap}_{tc}$ — 装机容量（吨）
- $L_t, \tau$ — 储藏天数、预冷时限（2小时）
- $H, \gamma$ — 采收窗口天数（90天）、峰值因子（1.8）

**损耗与碳排放参数**：
- $\alpha_i, \beta_t$ — 损耗函数参数（SPO学习）
- $e_{\gamma}, c_f$ — 单位能耗、碳因子
- $\lambda_L, \lambda_C$ — 损耗单价（3000元/吨）、碳价（50元/吨CO₂）

### 1.3 决策变量

**上层决策变量**：
- $z_{jtc} \in \{0,1\}$ — 是否在候选点 $j$ 建设类型 $t$ 容量 $c$ 的冷库

**下层决策变量**：
- $x_{ijt} \in [0,1]$ — 需求 $i$ 分配给设施 $j$ 类型 $t$ 的份额（连续）

### 1.4 三个目标函数

**目标1：总成本最小化**
$$
\min Z_1 = \sum_{j,t,c} z_{jtc} (f_{tc} + o_{tc}) + \sum_{i,j,t} x_{ijt} d_i \text{dist}_{ij} c_{\text{trans}} + \lambda_L Z_2 + \lambda_C Z_3
$$

**目标2：损耗吨数最小化**
$$
\min Z_2 = \sum_{i,j,t} x_{ijt} d_i (t_{ij} \alpha_{\text{trans}} m_t + \alpha_t^{for})
$$

**目标3：碳排放吨数最小化**
$$
\min Z_3 = \sum_{i,j,t} x_{ijt} d_i (e_{\gamma,t}/1000 + \text{dist}_{ij} \varepsilon/1000)
$$

### 1.5 约束条件

**C1. 通道份额约束**：
$$\sum_{j} x_{ijt} = s_t, \quad \forall i,t$$

**C2. 只能分配到开放设施**：
$$x_{ijt} \leq \sum_{c} z_{jtc}, \quad \forall i,j,t$$

**C3. 每候选点最多一个冷库**：
$$\sum_{t,c} z_{jtc} \leq 1, \quad \forall j$$

**C4. 最大设施数限制**：
$$\sum_{j,t,c} z_{jtc} \leq N_{\max}$$

**C5. 预冷时限约束（2h）**：
$$x_{ij,\text{precool}} = 0 \quad \text{if } t_{ij} > 2h$$

**C6. 峰值库存容量约束（v3.0核心）**：
$$\sum_{i} x_{ijt} d_i \frac{L_t}{H} \gamma \leq \sum_{c} z_{jtc} \text{cap}_{tc}, \quad \forall j,t$$

### 2.2 方法① KKT转化：双层→单层 (Bilevel → Single-level via KKT)

#### 2.2.1 双层模型的挑战

**原始双层结构**：
```
[上层] min_{z} F(z, x*(z))
       s.t. 上层约束

[下层] x*(z) = argmin_{x} f(x | z)
              s.t. 下层约束(x, z)
```

**难点**：
- 下层是嵌套优化问题，计算复杂度高
- 无法直接用标准MIP求解器

#### 2.2.2 KKT转化原理

**Step 1：下层LP的KKT条件**

下层问题是**关于 $x$ 的线性规划**（给定上层 $z$）：
$$
\min_{x} \sum_{i,j,t} x_{ijt} d_i c_{ijt}
$$
$$
\text{s.t. } \sum_j x_{ijt} = s_t, \quad x_{ijt} \geq 0, \quad \text{etc.}
$$

引入**对偶变量**：
- $\alpha_i$ — 通道份额约束对偶变量（自由符号）
- $\beta_{ijt} \geq 0$ — 非负约束对偶变量
- $\gamma_{jt} \geq 0$ — 容量约束对偶变量

**KKT条件（一阶必要性）**：

1. **对偶可行性**：
$$
\alpha_i + \beta_{ijt} + d_i \gamma_{jt} \leq c_{ijt}, \quad \forall i,j,t
$$

2. **互补松弛**：
$$
x_{ijt} \cdot (\alpha_i + \beta_{ijt} + d_i \gamma_{jt} - c_{ijt}) = 0
$$
$$
\beta_{ijt} \cdot x_{ijt} = 0, \quad \gamma_{jt} \cdot \text{(松弛)} = 0
$$

3. **强对偶性**（LP最优性）：
$$
\sum_{i,j,t} x_{ijt} d_i c_{ijt} = \sum_i \alpha_i + \sum_{j,t,c} \beta_{ijt} z_{jtc} + \sum_{j,t,c} \gamma_{jt} \text{cap}_{tc} z_{jtc}
$$

**Step 2：大M法线性化互补松弛**

互补松弛条件 $x \cdot (gradient) = 0$ 是**双线性的**，需要线性化：

引入辅助二元变量 $w_{ijt} \in \{0,1\}$：
$$
x_{ijt} \leq M \cdot w_{ijt}
$$
$$
\alpha_i + \beta_{ijt} + d_i \gamma_{jt} - c_{ijt} \leq M \cdot (1 - w_{ijt})
$$

其中 $M$ 是充分大的常数（取20.0）。

**Step 3：单层MILP合并**

将上层目标、上层约束、下层KKT条件、大M线性化约束**全部合并**到一个模型：

```python
# 上层变量
z[j,t,c] ∈ {0,1}

# 下层变量（放松为连续）
x[i,j,t] ∈ [0,1]

# 对偶变量
alpha[i] ∈ ℝ
beta[i,j,t] ≥ 0
gamma[j,t] ≥ 0

# 目标函数：上层建设+运营成本
min Σ z[j,t,c] * (fixed + operate)

# 约束：上层约束 + KKT条件 + 大M线性化
```

**实现文件**：`src/models/bilevel_kkt.py`

#### 2.2.3 KKT转化的优势与局限

**优势**：
- ✅ 数学上严格，保留双层最优性
- ✅ 可用标准MIP求解器（Gurobi）
- ✅ 下层LP保证强对偶成立

**局限**：
- ⚠️ 变量数翻倍（引入对偶变量）
- ⚠️ 大M法可能导致数值不稳定
- ⚠️ 仅适用于下层是LP的情况

**项目定位**：
- KKT转化是**理论基础**，证明双层模型可单层化
- 实际主求解器采用**v3.0容量链直接单层MIP**（更高效）
- KKT实现作为**验证对照**，确保单层简化的合理性

### 2.3 方法② 增广ε-约束：多目标→单目标 (Augmented ε-Constraint)

#### 2.3.1 多目标优化的挑战

三个目标（成本、损耗、碳排放）通常**相互冲突**：
- 降低成本 → 可能增加运输距离 → 损耗↑
- 降低碳排放 → 可能需要气调库 → 成本↑

需要找到**Pareto前沿**：所有非支配解的集合。

#### 2.3.2 ε-约束法原理

**核心思想**：将 $k-1$ 个目标转化为**约束**，只优化1个主目标。

**标准形式**：
$$
\min f_1(x) \quad \text{（主目标：成本）}
$$
$$
\text{s.t. } f_2(x) \leq \varepsilon_2 \quad \text{（损耗约束）}
$$
$$
f_3(x) \leq \varepsilon_3 \quad \text{（碳排放约束）}
$$
$$
x \in X \quad \text{（原可行域）}
$$

**扫描Pareto前沿**：
1. 固定 $\varepsilon_2, \varepsilon_3$ 的一组值
2. 求解单目标MIP → 得到一个Pareto点
3. 改变 $\varepsilon_2, \varepsilon_3$，重复步骤2
4. 收集所有非支配解 → **认证Pareto前沿**

**增广ε-约束改进**（避免弱Pareto解）：

在目标函数中加入**松弛变量的小权重**：
$$
\min f_1(x) + \delta \cdot (s_2 + s_3)
$$
$$
\text{s.t. } f_2(x) - s_2 = \varepsilon_2, \quad f_3(x) - s_3 = \varepsilon_3
$$
$$
s_2, s_3 \geq 0, \quad \delta \ll 1
$$

其中 $\delta = 10^{-6}$ 量级，确保优先优化主目标。

#### 2.3.3 实现细节

**ε网格生成**：
```python
# 先求每个目标的单独最优值
loss_min = solve_single_objective("loss")
carbon_min = solve_single_objective("carbon")

# 生成ε网格（线性或对数间隔）
eps_loss_grid = linspace(loss_min, loss_max, 10)
eps_carbon_grid = linspace(carbon_min, carbon_max, 10)

# 笛卡尔积扫描
for eps_L in eps_loss_grid:
    for eps_C in eps_carbon_grid:
        sol = solve_epsilon_constrained(eps_L, eps_C)
        pareto_front.add(sol)
```

**实现文件**：`src/models/epsilon_constraint.py`

#### 2.3.4 ε-约束法的优势

**优势**：
- ✅ 精确方法，生成**认证的Pareto前沿**
- ✅ 每次求解是标准单目标MIP，可用Gurobi
- ✅ 可以控制前沿密度（调整ε网格）

**局限**：
- ⚠️ 计算成本高（需多次求解MIP）
- ⚠️ ε网格密度与计算时间的权衡

**项目成果**：
- 在S1（9候选点）、S2（18候选点）上生成认证Pareto前沿
- 作为NSGA-III、ALNS启发式的**评价基准**
- 证明启发式前沿被精确前沿**完全支配**

### 2.5 方法④ Benders分解 + AI cut管理：鲁棒性增强

#### 2.5.1 Benders分解原理

**核心思想**：将MIP分解为**主问题（Master）**和**子问题（Subproblem）**，迭代生成cuts逐步收紧。

**主问题（设施选址与容量）**：
```
min η
s.t. z ∈ {0,1}^{J×T×C}
     Σ z[j,t,c] ≤ N_max
     Σ z[j,t,c] ≤ 1  ∀j
     η ≥ Q(z) + cuts   # 下界逼近
```

其中 $\eta$ 是辅助变量，逐步逼近真实运营成本 $Q(z)$。

**子问题（需求分配优化）**：

给定上层开放设施 $\bar{z}$，求解下层LP：
```
Q(z̄) = min Σ x[i,j,t] * d_i * cost[i,j,t]
       s.t. Σ x[i,j,t] = s_t  ∀i,t
            x[i,j,t] ≤ z̄[j,t]
            Σ x[i,j,t] * d_i ≤ cap[j,t] * z̄[j,t]
            x ≥ 0
```

**对偶子问题（生成cuts）**：

子问题是LP，可以用**对偶理论**生成Benders cuts：
```
Dual variables:
  α[i] → 通道份额约束
  β[i,j,t] → 分配上界约束
  γ[j,t] → 容量约束

Benders cut:
  η ≥ Σ α[i] * s_t + Σ β[i,j,t] * z[j,t] + Σ γ[j,t] * cap[j,t] * z[j,t]
```

**迭代流程**：
```
初始化：主问题无cuts，z任意可行
Loop:
    1. 固定z̄，求解子问题 → 得到Q(z̄)和对偶解(α, β, γ)
    2. 用对偶解生成Benders cut
    3. 将cut加入主问题
    4. 重新求解主问题 → 更新z
    5. 如果 |η - Q(z̄)| < ε，收敛
```

#### 2.5.2 AI cut管理机制

**问题背景**：
传统Benders在每次迭代后会积累**大量cuts**（几十到上百条），导致：
- 主问题求解变慢（约束数↑）
- 很多"旧cuts"对当前迭代贡献很小

**AI cut管理目标**：
在有限的cut预算 $K$ 下（例如K=8），智能选择**最有价值的cuts**保留在主问题中。

#### 2.5.3 AI融合增强：核心实现

**Step 1：图编码器（GNN轻量消息传递）**

将冷库布局问题建模为**需求节点-候选设施二分图**：

```python
# 节点特征
demand_features = [产量, 坐标, 候选属性]  # 维度：|I| × d_I
candidate_features = [容量, 成本, 坐标]    # 维度：|J| × d_J

# 边特征
edge_features = [距离, 时间, 是否可预冷]   # 维度：|I|×|J| × d_E

# 图嵌入（消息传递）
h_I = MessagePassing(demand_features, edge_features)
h_J = MessagePassing(candidate_features, edge_features)
h_graph = Aggregate(h_I, h_J)  # 问题级嵌入
```

实现：`src/algorithms/gnn_encoder.py`

**Step 2：Cut特征提取（16维）**

为每条Benders cut提取特征向量：

| 特征ID | 特征名称 | 说明 |
|:-----:|---------|------|
| 1 | rhs | cut右端项（目标函数下界贡献） |
| 2 | coef_count | 非零系数个数 |
| 3-5 | coef_min/max/mean | 系数统计量 |
| 6 | coef_l1_norm | L1范数（系数绝对值和） |
| 7 | coef_l2_norm | L2范数 |
| 8-9 | coef_std/cv | 标准差、变异系数 |
| 10 | iteration_number | 生成cut的迭代编号 |
| 11-12 | master_obj/bound | 主问题目标值与下界 |
| 13 | gap_pct | 当前gap百分比 |
| 14 | recency_score | 时近性分数（越近越高） |
| 15-16 | active_count/ratio | cut被激活次数/比例 |

实现：`src/algorithms/cut_features.py`

**Step 3：上下文Bandit式Cut评分器**

将**图嵌入 + cut特征**拼接后，用可解释评分公式：

```python
def score_cut(cut_features, graph_embedding):
    # 提取关键特征
    rhs = cut_features[0]
    coef_l1 = cut_features[6]
    gap_pct = cut_features[13]
    coef_count = cut_features[1]
    compactness = 1.0 / (1.0 + coef_count)
    
    # 可解释评分公式
    score = (
        0.40 * rhs +           # 下界贡献
        0.25 * coef_l1 +       # 系数强度
        0.20 * gap_pct +       # 当前gap紧迫性
        0.15 * compactness     # 紧凑性
    )
    
    return score, {
        "dominant_factors": ["rhs", "coef_l1"],
        "reason_text": f"得分主要由rhs={rhs:.3f}和coef_l1={coef_l1:.3f}驱动"
    }
```

**Step 4：Cut排序与保留策略**

```python
# 每次迭代后
all_cuts = [cut_1, cut_2, ..., cut_N]

# 用AI评分器排序
scored_cuts = [(score_cut(c), c) for c in all_cuts]
scored_cuts.sort(reverse=True)

# 保留Top-K
if len(scored_cuts) > K:
    kept_cuts = [c for (s, c) in scored_cuts[:K]]
    dropped_cuts = [c for (s, c) in scored_cuts[K:]]
else:
    kept_cuts = all_cuts

# 只把kept_cuts加入主问题
for cut in kept_cuts:
    master_problem.addConstr(η ≥ cut.rhs + cut.coeffs @ z)
```

实现：`src/algorithms/benders_ai.py`

### 2.6 方法⑤ NSGA-III / ALNS 元启发式对比基线

#### 2.6.1 为何需要启发式对比？

**研究问题**：
精确方法（ε-约束 + Gurobi）虽然能认证最优性，但计算成本高。启发式方法快100-200倍，但解质量如何？

**对比目标**：
在**相同可行域、相同评估器**下，量化精确方法与启发式方法的：
- 成本偏差
- Pareto前沿质量
- 求解时间权衡

#### 2.6.2 NSGA-III（第三代非支配排序遗传算法）

**核心思想**：
使用**参考点法**维持Pareto前沿多样性。

**算法流程**：
```
1. 初始化种群（可行性偏置采样）
2. 非支配排序 → 分层
3. 参考点关联 → 保持分布
4. 遗传操作（交叉、变异）
5. 环境选择 → 下一代
6. 重复2-5直到收敛
```

**编码方式**：
```python
# 染色体 = [设施开放向量 | 分配矩阵]
chromosome = {
    "facilities": [
        {"site": "C1", "type": "precool", "capacity": 10},
        {"site": "T4", "type": "ca", "capacity": 30},
        # ...
    ],
    "assignments": x[i,j,t]  # 39×27×4矩阵
}
```

**可行性偏置采样**：
- 问题：随机整数基因型在高维分配下几乎必然不可行
- 解决：先生成可行设施配置，再用贪心/随机方式生成分配

**实现**：`src/algorithms/heuristics_v3.py` (NSGA-III)

#### 2.6.3 ALNS（自适应大邻域搜索）

**核心思想**：
- **破坏（Destroy）**：移除部分解的组件
- **修复（Repair）**：重新构造完整解
- **自适应权重**：根据历史收益调整算子选择概率

**破坏算子**（3种）：
1. **随机破坏**：随机移除k个设施
2. **最差破坏**：移除利用率最低的k个设施
3. **关闭设施**：移除某个设施并重新分配需求

**修复算子**（2种）：
1. **贪心修复**：按单位成本最小优先
2. **最便宜插入**：选择边际成本最小的设施

**自适应权重更新**：
```python
# 每100次迭代更新一次权重
if iteration % 100 == 0:
    for operator in [destroy_ops, repair_ops]:
        score = operator.accept_count / (operator.use_count + 1e-6)
        operator.weight = 0.8 * operator.weight + 0.2 * score
```

**Pareto归档**：
维护多设施数的Pareto解集合，每次找到非支配解时更新。

**实现**：`src/algorithms/heuristics_v3.py` (ALNS)

#### 2.6.4 共享评估器（关键设计）

**问题**：
如果精确方法和启发式用**不同的目标函数**或**不同的可行域**，对比结果无意义。

**解决方案：共享评估器**

```python
class LayoutEvaluatorV3:
    """求解器无关的布局方案评估器"""
    
    def evaluate(self, solution):
        """
        输入：solution = {facilities: [...], assignments: x[i,j,t]}
        输出：{
            "cost": 总成本,
            "loss_ton": 损耗吨数,
            "carbon_ton": 碳排放吨数,
            "feasible": True/False,
            "violations": [...]
        }
        """
        # 相同的成本计算
        cost = self._calc_cost(solution)
        
        # 相同的损耗计算
        loss = self._calc_loss(solution)
        
        # 相同的碳排放计算
        carbon = self._calc_carbon(solution)
        
        # 相同的约束检查
        feasible = self._check_constraints(solution)
        
        return {"cost": cost, "loss_ton": loss, "carbon_ton": carbon, "feasible": feasible}
```

**确保一致性**：
- ✅ 精确方法、NSGA-III、ALNS都调用同一个evaluator
- ✅ 相同的参数（碳价、损耗单价、距离矩阵）
- ✅ 相同的约束（最大设施数、容量、预冷时限）

**实现**：`src/algorithms/layout_evaluator_v3.py`

#### 2.6.5 对比实验结果

**实验设置**：
- S1场景（9候选点）、S2场景（18候选点）
- 每种方法运行3次（不同随机种子）
- 超体积估计：蒙特卡洛采样（10,000点）

**结果汇总**：

| 方法 | 平均成本偏差 | 超体积比 | 平均耗时（秒） | 前沿质量 |
|:----:|:----------:|:-------:|:------------:|:--------:|
| **精确ε-约束** | **0%** (基准) | **1.000** | **59.07** | ✅ 认证最优 |
| NSGA-III | 0.36% | 0.769 | 1.34 | ⚠️ S2被完全支配 |
| ALNS | 8.10% | 0.641 | 0.34 | ⚠️ S2被完全支配 |

**关键发现**：

- ⚠️ ALNS成本偏差大（8.10%），前沿质量更差

**结论**：
